## Intended product

The original destination goal was a reusable, headless, contract-first template
for AI-assisted software and hardware projects. It combined the OOP template's
modular architecture with selected capabilities from the universal template.
The original OOP example established typed contracts, presentation-only UI,
feature implementations behind interfaces, dependency injection, shared
behavioral tests, and import-boundary checks.

The recovered headless migration brief names these capabilities:

1. Durable decisions, state, open loops, source records, and handoffs.
2. Project intake and generation.
3. Multiple AI-platform instruction entrypoints.
4. Model routing, budgets, and bounded retries.
5. Worker launching and monitoring.
6. Hardware and firmware verification controls.
7. GitHub CI and guarded closeout.

It also calls for fresh-checkout setup, distinct generated-project identity and
inactive approval, and clear separation of deterministic harness checks from
paid-model connectivity and real hardware evidence.

## Scope distinction

Later owner direction narrowed the M1–M6 implementation campaign to a bounded
offline workflow foundation. That foundation is delivered, but its completion
does not establish completion or abandonment of the broader product goals
above. Historical briefs describe intent; they do not grant current execution,
provider, hardware, publication, or merge authority.

The recovered handoff itself records remaining gaps including project
generation, native platform entrypoints, GitHub CI, and an ordinary usable path
for the broader reusable template. Consult current implementation and evidence
before treating any historical gap as a present-day status.
